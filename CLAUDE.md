# Конструктор «Своя игра»

Веб-конструктор игр в стиле «Своя игра». Игры собирают коллеги и друзья без технических навыков: им нужны только браузер и ссылка. Игра проводится на одном большом экране, ведущий управляет с ноутбука.

Полный план, требования и модель данных — `docs/PLAN.md`. Обсуждение и проектирование идут отдельно, в проекте claude.ai «Конструктор игры»; сюда приходят готовые задачи.

## Кто работает с кодом

Владелец проекта — начинающий разработчик. Поэтому:
- Объясняй, что сделал и зачем, простым русским языком, без жаргона. Коротко.
- Все тексты интерфейса и комментарии в коде — на русском.
- Сообщения коммитов — на русском, коротко, по сути («Табло с тестовой игрой»).
- Не добавляй библиотеки сверх перечисленных ниже без согласования.
- Если задача расходится с `docs/PLAN.md` — спроси, а не переписывай план сам.

## Стек и команды

React + TypeScript + Vite, Tailwind CSS 4 (`@tailwindcss/vite`), Dexie (IndexedDB), JSZip (файл игры .zip; грузится только при открытии и отправке файла). Для разработки — Vitest (автопроверки, на сайт не попадает). Windows, PowerShell.

- `npm run dev` — сайт для разработки (http://localhost:5173)
- `npm run build` — проверка типов и сборка; запускай перед каждым коммитом
- `npm test` — автопроверки (Vitest); тоже перед каждым коммитом. Публикация (`pages.yml`) их запускает сама: не прошли — сайт не обновляется
- `npm run test:watch` — проверки перезапускаются сами при каждом сохранении файла
- `npm run lint` — oxlint
- `npm run build:dev` — сборка тестового сайта (режим `devsite`, папка `dist-dev`)

## Ветки и сайты

- **`dev`** — тесты. Вся новая работа сначала идёт сюда. Отправка в dev публикует тестовый сайт https://salampopalamm.github.io/svoya-igra/dev/ — с меткой «DEV» и своим хранилищем игр (`src/site.ts`: `IS_DEV_SITE`, `APP_KEY`), настоящие игры он не видит и не трогает. Игру между сайтами переносят файлом .zip.
- **`main`** — основной проект, сайт для всех: https://salampopalamm.github.io/svoya-igra/. Сюда попадает только проверенное на dev — слиянием dev → main и только по слову владельца.
- Любые имена в хранилище браузера (база, localStorage, канал связи окон) начинай с `APP_KEY`, иначе тестовый сайт смешается с основным.
- Публикация — `.github/workflows/pages.yml`: при отправке в main или dev собираются обе ветки (main — в корень, dev — в папку `dev/`), перед сборкой — `npm test`. Не собрался main — не публикуется ничего (остаётся прежний сайт). Не собрался dev — main всё равно публикуется, на `/dev/` — страница-заглушка «Тестовая версия сейчас не собралась», а на GitHub — предупреждение.

## Сайт

- Сайт собирается и выкладывается сам (см. «Ветки и сайты»). Пути в сборке относительные (`base: './'` в `vite.config.ts`), поэтому адреса внутри сайта не начинай с `/`. Проверить сборку «как на GitHub» — запуск `pages-preview` в `.claude/launch.json` (http://localhost:4173/svoya-igra/).

## Архитектура

- `src/types.ts` — модель данных (Game, Round, Category, Question, Team, Player, QuestionTree, Rule).
- `src/db.ts` — хранение в браузере (Dexie): таблица `games` — игры, таблица `media` — сами файлы (картинки, музыка, видео); в игре только ссылка `MediaRef`. Меняешь вид сохранённых данных — новая версия базы с переводом старых игр (`db.version(N).upgrade`).
- Вопрос — это слайды (`Question.slides`): обычно первый — текст или описание задания, следующие — картинка, музыка, видео. Ведущий листает их ← / →, зал показывает текущий (`LiveState.slideIndex`). На слайде (и в ответе) может быть до 8 картинок: первая — `Content.media`, остальные — `Content.more`, шаблон — `Content.layout`; функции — `src/pictures.ts` (`contentMedia` — все файлы слайда: используй её, а не `.media`, когда собираешь или удаляешь файлы), показ — `ContentMedia` в `MediaView.tsx`.
- `src/components/MediaView.tsx` — показ файла и слайда. Музыка играет в окне пульта (браузер не глушит звук там, где ведущий кликает), в зале — значок ♪. Видео наоборот: со звуком играет в зале, на пульте — копия без звука и кнопки; команды идут через `LiveState.video` (номер команды `seq`), связь с экранами — контекст `src/videoControl.ts`.
- Фрагмент музыки или видео — `MediaRef.clip` (`{ start?, end? }`, секунды; функции и хук `useClip` — `src/clip.ts`): пульт и зал играют только его, видео на конце фрагмента пульт останавливает и в зале. В редакторе вместо плеера — `components/ClipEditor.tsx` («Играть: с … до …», «⏱ отсюда», «▶ Проиграть фрагмент»).
- Экран зала начинается с заставки «Нажмите, чтобы начать» (клик разрешает звук и полный экран) и сообщает пульту, готов ли он (сообщение `hall` в `live.ts`).
- Сигнал «время вышло» — `src/sounds.ts`, играет на пульте, синтезируется (Web Audio); выключатель — `Game.theme.sounds.enabled` («Звук таймера» на пульте). Сигналов «верно / неверно» нет по решению владельца — не добавляй.
- `src/live.ts` — «живое» состояние партии и канал `BroadcastChannel('svoya-igra')` между окнами.
- Адреса (hash): `#/` — «Мои игры», `#/play/<id>` — пульт ведущего, `#/edit/<id>` — редактор игры, `#/teams/<id>` — «Команды и игроки», `#/screen` — экран зала, `#/new` — мастер «Быстрая игра». Редактор, «Команды» и мастер грузятся отдельно, когда их открывают (`lazyScreen` в `App.tsx`: если сайт обновился, страница один раз перезагружается); пульт и зал — в основной части сайта, чтобы игра не зависела от интернета.
- Экраны, которые правят игру (редактор, команды), сохраняют её через хук `src/useSavedGame.ts`. Сохранение игры (`saveGame`, `updateStoredGame` в `db.ts`) сообщает другим окнам (канал `<APP_KEY>:games`, `onGameSavedElsewhere`): `useSavedGame` берёт свежую версию, чтобы правка в редакторе не вернула старое оформление, поставленное пультом.
- **Починка игры** — `src/repairGame.ts`: каждая игра, прочитанная из хранилища (`getGame`, `listGames`, `updateStoredGame`) или из файла .zip, проходит через `repairGame` — недостающее заполняется, мусор выбрасывается. **Добавляешь поле в модель данных (`types.ts`) — добавь его и в `repairGame`, иначе оно пропадёт при открытии игры.**
- Страховка от белого экрана — `components/ErrorBoundary.tsx`: общая в `App.tsx` (кнопки «Попробовать снова» / «Мои игры»), у пульта своя (`HostGuard`: «Закрыть вопрос и вернуться к табло» — `closeSavedQuestion` в `live.ts`). Зал зрителям ошибку не показывает: вопрос или табло просто пустеют, при сбое всего зала — «Секунду…»; следующее состояние от пульта пробует снова, заставку повторно не показывает.
- Пульты узнают друг друга (сообщения `host` / `host-bye` в `live.ts`): если пульт открыт в двух окнах, оба показывают предупреждение.
- Финал — раунд с `kind: 'final'` (переключатель в редакторе): каждая категория — тема с одним вопросом. Шаги «темы → ставки → вопрос → итоги» — `LiveState.final`, функции — `src/final.ts`; пульт — `components/FinalHost.tsx` (+ `FinalAnswers` внизу `QuestionView`), зал — `components/FinalScreen.tsx`. Вопрос финала идёт обычным `current`, поэтому слайды, видео и таймер работают как всегда; Esc и Пробел его не закрывают — только «Раскрыть итоги».
- Ветвящийся вопрос — `Question.tree` (шаги `TreeNode` с вариантами: баллы и следующий шаг; шаг без вариантов — конец ветки). Логика и проверка — `src/tree.ts`, редактор — `components/TreeEditor.tsx` (списком шагов, без React Flow — решение владельца), общие поля — `components/ContentEditor.tsx`. В игре ход по дереву — `LiveState.branch`; пульт — `components/BranchHost.tsx` внутри `QuestionView` (проп `branch`), зал — `ScreenQuestion` (проп `step`). Содержимое дерева учитывают `questionContents` / `mediaIdsOf` / `isEmptyQuestion` в `game.ts`.
- Особый вопрос — `Question.special` (`correct`: ×2 / ×3 за верный, `wrong: 0` — без минуса, `forAll` — отвечают все команды сразу); функции — `src/special.ts` (`correctPoints`, `wrongPoints`, `isForAll`, `specialTitle`), счёт — в `play.ts` (`answerCorrect` / `answerWrong`; для всех — `markAll`, `revealAll`, отметки — `LiveState.marks`). Пульт: пометка в ячейке и у цены, внизу — `components/AllAnswers.tsx`; зал: надпись над вопросом (`title` в `ScreenQuestion`), на табло — ничего. В редакторе — блок «⭐ Особый вопрос» (`SpecialEditor` в `QuestionEditor.tsx`). На дерево, финал, кота и аукцион не действует.
- «Кот в мешке» и аукцион — `Question.kind` (`'cat-in-bag'` / `'auction'`, выбирается в «Вид вопроса» редактора) + `Question.cat` (тема, цена; пусто — цена ячейки) / `Question.auction` (`'all'` — торгуются все, `'turn'` — только чей ход). Правила (предел ставки, кто следующий) — `src/catAuction.ts`, ход — `play.ts` (`giveCat`, `auctionSetBet`, `auctionStart`, `answerPoints`; состояние — `LiveState.cat` / `LiveState.auction`). Сначала шаг «до вопроса»: кота отдают (номер команды или кнопка — тот же `selectAnswering`), на аукционе ведущий вписывает ставки; зал в это время показывает заставку `components/CatAuctionScreen.tsx`, пульт — `components/CatAuctionHost.tsx` внизу `QuestionView` (проп `catAuction`). Кота не перехватывают; на аукционе после ошибки сразу отвечает следующая по кругу команда со ставкой. На табло зала — обычная ячейка (сюрприз).
- Скрытый вопрос — `Question.hidden`; открывает его вариант дерева (`unlockQuestionId`) или ведущий кликом на пульте. Открытые — `LiveState.unlockedIds`; `Board` рисует закрытую ячейку «?» (зал) / «🔒 скрыт» (пульт), открытую — акцентом. Список скрытых для выбора — `hiddenQuestions` в `game.ts`.
- Правила «ЕСЛИ → ТО» — `Game.rules`, логика — `src/rules.ts` (`readyRules`, `describeRule`, `ruleProblem`), редактор — `components/RulesEditor.tsx`. Правило не выполняется само: пока вопрос закрыт, пульт показывает плашку «Выполнить / Пропустить» (решение владельца); выполненные и пропущенные — `LiveState.rulesDone`. Скрытый раунд — `Round.hidden`, открытые — `LiveState.unlockedRoundIds`; картинка правила в зале — `LiveState.shownMedia`, надпись — `LiveState.shownText`. Условия: набрала N, ошиблась N раз подряд (по журналу — `wrongStreak`), отстаёт от лидера на N, сыгран раунд / категория / вопрос; действия: открыть скрытый вопрос / раунд, картинка или надпись в зале, дать баллы (`then.points`, пишется в журнал), передать ход. Кому баллы и ход — `then.target`: `trigger` (команда из условия — `triggerTeams`), `leader`, `last` (`targetTeam`); кто это, решается в момент «Выполнить». Выполняет `runRule` в `play.ts`.
- Раунды: в игре их может быть несколько (`Game.rounds`). Какой раунд на табло — `LiveState.roundId` (пульт переключает, зал показывает); в редакторе — вкладки. Раунд по id — `roundById` в `game.ts`.
- Файл игры (.zip) — `src/gameFile.ts`: `game.json` (`format: 'svoya-igra'`, `version`, `game`, список `media`) + `media/<id>.<расширение>`. «Открыть файл игры» и «Отправить файлом» — в «Моих играх»; открытая игра всегда получает новый id. Когда игру отправляли файлом — `exportedAt` / `markExported` (localStorage); «Мои игры» показывают у игры «копия файлом … ✓ / после неё игру меняли / нет», занятое место (`storageUsed`) и просят браузер не стирать хранилище (`protectStorage` в `db.ts`).
- Участники — один общий список `Game.players`; команда игрока — поле `teamId`, капитан — `locked`. Экран `screens/TeamsApp.tsx` (+ `components/PlayersList.tsx`) показывает их двумя способами: слева список, справа плашки в карточках команд. Случайное распределение — `distributeRandomly` в `game.ts`.
- Файл из хранилища на экране — хук `src/useMediaUrl.ts` (ссылки на файлы общие на всё окно и не освобождаются). Предзагрузка — `src/preload.ts` (`usePreload`): пульт и зал при открытии загружают и проверяют все файлы игры (`allMediaRefs` в `game.ts`); зал сообщает пульту, сколько готово (сообщение `hall-media`), пульт показывает строку `components/MediaStatus.tsx`.
- Значок команды — `Team.emoji` (набор `TEAM_EMOJI` в `game.ts`) или `Team.logo` (своя картинка, важнее эмодзи); показывает `components/TeamIcon.tsx`, выбирается в карточке команды на экране «Команды».
- Вид команд в зале — `Game.theme.teamView` (`photos` — колонка `components/TeamsColumn.tsx` справа от табло, `compact` — полоса `Scoreboard` снизу) и `theme.showPhotos`. Переключается на пульте; пульт пишет в хранилище только оформление (`updateStoredGame` в `db.ts`), не счёт партии.
- Мастер «Быстрая игра» (`#/new`, `screens/WizardApp.tsx` + `src/wizard.ts`): шаги «Название и оформление → Вопросы таблицей → Команды»; оформление — тот же `components/ThemeEditor.tsx`, что в редакторе, хранится в `Draft.theme` (`draftTheme`). Таблица — строки `Row` (категория, стоимость, вопрос, ответ, файл), вставка из Excel по Ctrl+V (`parseTable`), недочёты — `rowProblems`, игра собирается в `gameFromDraft`: текст вопроса — первый слайд, файл строки — второй (у строки, как у слайда, может быть до 8 картинок: `Row.media` + `Row.more`). Черновик живёт в localStorage, пока игра не создана.
- Автопроверки лежат рядом с проверяемым файлом: `game.test.ts`, `play.test.ts` (счёт, перехват, ход, ветка, финал целиком), `tree.test.ts`, `final.test.ts`, `rules.test.ts`, `wizard.test.ts`, `pictures.test.ts` (+ расстановка), `repairGame.test.ts`, `live.test.ts` (таймер, размеры), `hostKeys.test.ts` (горячие клавиши), `log.test.ts` (журнал), `clip.test.ts` (фрагмент), `special.test.ts` (особые вопросы), `catAuction.test.ts` (кот и аукцион). Маленькие игры для них собирает `src/testing.ts` (`game`, `round`, `cat`, `q`, `emptyQ`, `team`, `step`, `tree`, `picture`). Новая или изменённая чистая функция — добавь проверку; нашли ошибку — сначала проверка, которая её ловит, потом исправление.
- `src/game.ts` — чистые функции над игрой: найти, изменить, добавить, удалить, переставить вопрос или категорию, копия игры. Новую правку игры пиши здесь, а не прямо в экране.
- Проверка игры — `gameProblems` / `questionProblem` в `game.ts` (вопрос без ответа, ответ без вопроса, пустые ячейки, категории, раунды; одинаковая стоимость — не недочёт). В редакторе — блок «Проверка игры» над категориями.
- Редактор (`screens/EditorApp.tsx` + `components/QuestionEditor.tsx`) меняет игру в хранилище и сохраняет после каждой правки. В нём своя сетка категорий (не `Board`): название, ↑ ↓, ячейки вопросов, «+», «Удалить». Файлы добавляются через `addMediaFile` в `db.ts` — большие картинки он сначала уменьшает (`src/shrinkImage.ts`: длинная сторона до 2560 точек, фото → JPEG, PNG/WebP → WebP, GIF и SVG не трогает; оставляет исходник, если копия не меньше); файл, на который больше нет ссылок, удаляется (`deleteMediaIfUnused`). Брошенные файлы (ни в одной игре и ни в черновике мастера) находит `findUnusedMedia` — кнопка «Убрать ненужные файлы» в «Моих играх». Большие фото, сохранённые раньше, уменьшает `shrinkStoredImages` (кнопка «Уменьшить большие фото», кандидаты — `findBigImages`; обработанные запоминаются в localStorage и больше не предлагаются). Файл игры больше 500 МБ (`mediaBytes`) «Мои игры» всё равно сохраняют и открывают — только пишут в строке «Собираю / Открываю…», что это может занять несколько минут, а при неудаче советуют сжать видео (решение владельца: предупреждение не должно мешать сохранить игру).
- Содержимое игры живёт в хранилище, ход партии (счёт, сыгранные ячейки) — в `LiveState`. При открытии пульта они склеиваются (`mergeProgress` в `src/game.ts`), поэтому правки в редакторе не сбрасывают начатую партию. Партия (и репетиция) хранится в localStorage **отдельно для каждой игры** (`<APP_KEY>:live:v3:<id игры>`, функции `loadState(gameId)` и т. п. в `live.ts`): открыли другую игру — счёт первой остаётся; «Мои игры» помечают начатую партию (`hasSavedState`), удаление игры стирает и её партию.
- Порядок ответа (`LiveState`): `turnTeamId` — чей ход, ходит по кругу (`nextTeamId` в `game.ts`) после каждого закрытого вопроса; при открытии вопроса отвечает эта команда. «Неверно» — минус стоимость, команда попадает в `triedTeamIds`, и вопрос можно перехватить любой другой (неверный перехват — тоже минус). «Верно» — плюс и закрыть.
- Таймер вопроса: длительность — `Question.timerSec`, ход таймера — `LiveState.timer` (момент окончания `endsAt` или остаток на паузе; функции в `live.ts`, тиканье — хук `src/useTimeLeft.ts`). Запускает ведущий (T), время можно выбрать на пульте у любого вопроса; зал только показывает. «📌 Закрепить» — `Theme.pinnedTimerSec`: ставится на каждый вопрос и важнее `timerSec` (решение владельца). Заметка ведущему — `Question.hostNote`, в зале её нет.
- Кнопки пульта (предпросмотр, скрыть зал, фон, шрифт, вид команд…) — по id в `renderControl` (`HostApp.tsx`); категории и закрепление — `src/hostControls.ts` (закреплённые хранятся в localStorage), панель ⚙ — `components/HostSettings.tsx`. Новую кнопку пульта добавляй туда же: id, категория, `renderControl`.
- Горячие клавиши пульта — `src/hostKeys.ts` (`hostKey`: клавиша → команда, проверки — `hostKeys.test.ts`); выполняет команды пульт в своём обработчике keydown. Клавиши смотрим по месту (`e.code`), поэтому они работают и в русской раскладке.
- Памятка «Как провести игру» (проектор, клавиши, что делать при сбое) — `components/HowToRun.tsx`, открывается с пульта. Меняешь горячие клавиши или порядок вывода зала — поправь и её.
- Журнал партии — `LiveState.log` (`src/log.ts`: `LogEntry`, `withLog`, `teamStats`, `wrongStreak`, `logToCsv`). Пишут его функции `play.ts` (верно, неверно, «никто не ответил» — `closeQuestion`, ветка, финал, поправки ведущего `adjustScore` / `setScore`); новое изменение счёта — тоже с записью в журнал. Панель на пульте — `components/GameLog.tsx` (кнопка `log`), «Сохранить в Excel» — CSV. Ctrl+Z и репетиция откатывают журнал вместе с партией.
- **Правила хода партии — `src/play.ts`** (чистые функции над `LiveState`: `openCell`, `answerCorrect`, `answerWrong`, `selectAnswering`, `withClosed`, `chooseBranch`, `toggleTimer`, `runRule`, финал `finalShowQuestion` / `finalReveal` …; проверки — `play.test.ts`). Пульт их только вызывает: `commit(answerCorrect(live, teamId))`. Невозможное сейчас действие возвращает то же состояние — `commit` его пропускает, и в историю Ctrl+Z пустой шаг не попадает. Новое правило игры пиши в `play.ts` с проверкой, а не в `HostApp.tsx`.
- Пульт (`screens/HostApp.tsx`) — единственный источник состояния партии; экран зала (`screens/ScreenApp.tsx`) только показывает то, что прислал пульт. Исключение — «Мышь в зале» (`LiveState.hallMouse`, по умолчанию включена — `hallMouseOn`, выключается в ⚙ пульта): зал присылает просьбу `hall-action` (`HallAction` в `live.ts`), пульт выполняет её в `handleHallAction` как свою кнопку; панель в зале — `components/HallMousePanel.tsx` (сворачивается в кнопку «▾ Панель» вверху посередине, это запоминается в localStorage зала). Сам зал игру не меняет.
- Вопрос в зале (`ScreenQuestion`) — без категории, цены, плашки «Отвечает» и шапки зала (решение владельца: всё место картинкам); кто отвечает — подпись в полосе команд, таймер — справа от текста вопроса. Заголовок только в финале («Финал · тема»).
- Сыгранную ячейку можно открыть снова только посмотреть: `LiveState.viewOnly` — без «Верно / Неверно», при закрытии ход не переходит.
- Репетиция (`LiveState.rehearsal`): партия до неё запоминается в localStorage (`saveRehearsal` в `live.ts`), в репетиции всё работает как в игре, «Закончить репетицию» возвращает запомненную партию. Порядок вопросов — `rehearsalCells` в `game.ts`. В отличие от предпросмотра, репетиция идёт в зал — с меткой «РЕПЕТИЦИЯ».
- Размеры в зале (`Theme.sizes`: табло, команды, фото, картинки, текст, таймер) — ползунки. Режим «Растянуть в зале» — `LiveState.resizeHall` (кнопка пульта `hall-resize`): зал рисует у объектов рамку и уголок (`components/Resizable.tsx`, контекст `ResizeContext` в `src/hallResize.ts`), пока тянут — меняет CSS-переменную у себя, отпустили — шлёт пульту `hall-action`; «Готово» — `resize-done`. Текст, картинки и таймер вопроса тянутся как ползунки (`size`, те же `Theme.sizes`). Каждая ячейка, категория, команда и части шапки — отдельно (решение владельца): `Theme.itemSizes` (ключи `cell:<id вопроса>`, `cat:<id>`, `team:<id>`, `head:title|round|turn`; `item-size`), переменная `itemVar(key)` в `theme.ts`; растянутая шире в строке (`itemGrow`, поэтому табло и полоса команд — строки flex, а не сетка) и крупнее целиком (zoom внутри рамки). Уголок отдельного объекта виден при наведении мыши. Сброс — кнопка в `SizeSliders`.
- Своя расстановка слайда — `Content.place` (рамки `Box` текста и каждой картинки в процентах области вопроса; функции — `src/placement.ts`: `defaultPlace`, `placeOf`, `clampBox`, `setContentPlace`). Есть `place` — зал рисует слайд через `components/PlacedSlide.tsx` (текст сам подбирает шрифт под рамку; ползунки «Текст» и «Картинки» на такой слайд не действуют), нет — обычная раскладка. Расставляют в предпросмотре редактора («Расставить самому»; в `HallPreview` есть команды, чтобы область вопроса была той же формы, что в зале) или прямо в зале в режиме «Растянуть» (`hall-action` `place`, пульт сохраняет вопрос через `updateStoredGame`). Убрали картинку — `withoutPicture` убирает и её рамку.
- **Предпросмотр вопроса и история отмен существуют только на пульте и никогда не попадают в зал.** Не добавляй их в `LiveState`. В редакторе есть свой предпросмотр «так увидит зал» — `components/HallPreview.tsx` (кнопка «Предпросмотр» в редакторе вопроса; тоже только локально).

## Дизайн

- Тёмная графитовая тема; акцент — инверсия (белое с чёрным текстом) или фирменный цвет клиента.
- Токены Tailwind в `src/index.css` (`@theme`): `bg-bg` #26272B, `bg-cell` #34363C, `border-line` #55585F, `text-muted` #C4C6CC, `bg-accent` / `text-on-accent` (акцент, по умолчанию белый / чёрный).
- Оформление игры (`Game.theme`) меняет только экран зала: `components/HallFrame.tsx` ставит CSS-переменные из `hallThemeStyle` (`src/theme.ts`: тоны, шрифты, акцент) на корень зала — классы Tailwind подхватывают их сами (на светлом тоне `text-white` становится тёмным). Подсветку «чей ход / кто отвечает» в зале пиши через `accent`, а не `white`. Картинки и видео вопросов помечены `data-media` (для «обесцветить медиа»). Пульт и редактор всегда графитовые. Размеры в зале (`Theme.sizes`, ползунки `components/SizeSliders.tsx`) — тоже CSS-переменные: `--board-scale`, `--teams-scale`, `--text-scale`, `--timer-scale` (CSS `zoom` на обёртке), `--photos-scale`, `--media-scale` (высота картинок). Корень зала помечен `data-hall`.
- Шрифты: `font-display` (Rubik Mono One) — заголовки, категории, номиналы; Inter — весь остальной текст, включая вопросы.
- Табло: категории строками, номиналы справа; сыгранная ячейка — красная (`--color-played`), пустое место — пунктирная рамка. Ячейки стоят по порядку (`sortByValue`, при равной цене — как в игре), а не по цене: в строке может быть восемь «400». В категории до 10 вопросов (`MAX_QUESTIONS`), готовые сетки 5 / 8 / 10, новая игра — 10. Номинал в ячейке масштабируется под её ширину (`@container` + `cqw`), чтобы «1000» помещался.
- Кнопки и цели касания не меньше 44 px; настоящие `<button>` и `<a>`.
