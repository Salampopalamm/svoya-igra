# Конструктор «Своя игра»

Веб-конструктор игр в стиле «Своя игра». Игры собирают коллеги и друзья без технических навыков: им нужны только браузер и ссылка. Игра проводится на одном большом экране, ведущий управляет с ноутбука.

Полный план, требования и модель данных — `docs/PLAN.md`. Обсуждение и проектирование идут отдельно, в проекте claude.ai «Конструктор игры»; сюда приходят готовые задачи.

## Стек и команды

React + TypeScript + Vite, Tailwind CSS 4 (`@tailwindcss/vite`), Dexie (IndexedDB), JSZip (файл игры .zip; грузится только при открытии и отправке файла). Windows, PowerShell.

- `npm run dev` — сайт для разработки (http://localhost:5173)
- `npm run build` — проверка типов и сборка; запускай перед каждым коммитом
- `npm run lint` — oxlint

## Архитектура

- `src/types.ts` — модель данных (Game, Round, Category, Question, Team, Player, QuestionTree, Rule).
- `src/db.ts` — хранение в браузере (Dexie): таблица `games` — игры, таблица `media` — сами файлы (картинки, музыка, видео); в игре только ссылка `MediaRef`. Меняешь вид сохранённых данных — новая версия базы с переводом старых игр (`db.version(N).upgrade`).
- Вопрос — это слайды (`Question.slides`): обычно первый — текст или описание задания, следующие — картинка, музыка, видео. Ведущий листает их ← / →, зал показывает текущий (`LiveState.slideIndex`).
- `src/components/MediaView.tsx` — показ файла и слайда. Музыка играет в окне пульта (браузер не глушит звук там, где ведущий кликает), в зале — значок ♪. Видео наоборот: со звуком играет в зале, на пульте — копия без звука и кнопки; команды идут через `LiveState.video` (номер команды `seq`), связь с экранами — контекст `src/videoControl.ts`.
- Экран зала начинается с заставки «Нажмите, чтобы начать» (клик разрешает звук и полный экран) и сообщает пульту, готов ли он (сообщение `hall` в `live.ts`).
- Сигналы «верно», «неверно», «время вышло» — `src/sounds.ts`, играют на пульте; стандартные синтезируются (Web Audio), свои файлы — `Game.theme.sounds`, правятся в редакторе (`components/SoundsEditor.tsx`).
- `src/live.ts` — «живое» состояние партии и канал `BroadcastChannel('svoya-igra')` между окнами.
- Адреса (hash): `#/` — «Мои игры», `#/play/<id>` — пульт ведущего, `#/edit/<id>` — редактор игры, `#/teams/<id>` — «Команды и игроки», `#/screen` — экран зала, `#/new` — мастер «Быстрая игра».
- Экраны, которые правят игру (редактор, команды), сохраняют её через хук `src/useSavedGame.ts`.
- Раунды: в игре их может быть несколько (`Game.rounds`). Какой раунд на табло — `LiveState.roundId` (пульт переключает, зал показывает); в редакторе — вкладки. Раунд по id — `roundById` в `game.ts`.
- Файл игры (.zip) — `src/gameFile.ts`: `game.json` (`format: 'svoya-igra'`, `version`, `game`, список `media`) + `media/<id>.<расширение>`. «Открыть файл игры» и «Отправить файлом» — в «Моих играх»; открытая игра всегда получает новый id.
- Участники — один общий список `Game.players`; команда игрока — поле `teamId`, капитан — `locked`. Экран `screens/TeamsApp.tsx` (+ `components/PlayersList.tsx`) показывает их двумя способами: слева список, справа плашки в карточках команд. Случайное распределение — `distributeRandomly` в `game.ts`.
- Файл из хранилища на экране — хук `src/useMediaUrl.ts`.
- Вид команд в зале — `Game.theme.teamView` (`photos` — колонка `components/TeamsColumn.tsx` справа от табло, `compact` — полоса `Scoreboard` снизу) и `theme.showPhotos`. Переключается на пульте; пульт пишет в хранилище только оформление (`updateStoredGame` в `db.ts`), не счёт партии.
- Мастер «Быстрая игра» (`#/new`, `screens/WizardApp.tsx` + `src/wizard.ts`): шаги «Название → Вопросы таблицей → Команды». Таблица — строки `Row` (категория, стоимость, вопрос, ответ, файл), вставка из Excel по Ctrl+V (`parseTable`), недочёты — `rowProblems`, игра собирается в `gameFromDraft`: текст вопроса — первый слайд, файл строки — второй. Черновик живёт в localStorage, пока игра не создана.
- `src/game.ts` — чистые функции над игрой: найти, изменить, добавить, удалить, переставить вопрос или категорию, копия игры. Новую правку игры пиши здесь, а не прямо в экране.
- Редактор (`screens/EditorApp.tsx` + `components/QuestionEditor.tsx`) меняет игру в хранилище и сохраняет после каждой правки. В нём своя сетка категорий (не `Board`): название, ↑ ↓, ячейки вопросов, «+», «Удалить». Файлы добавляются через `addMediaFile` в `db.ts`; файл, на который больше нет ссылок, удаляется (`deleteMediaIfUnused`).
- Содержимое игры живёт в хранилище, ход партии (счёт, сыгранные ячейки) — в `LiveState`. При открытии пульта они склеиваются (`mergeProgress` в `src/game.ts`), поэтому правки в редакторе не сбрасывают начатую партию.
- Порядок ответа (`LiveState`): `turnTeamId` — чей ход, ходит по кругу (`nextTeamId` в `game.ts`) после каждого закрытого вопроса; при открытии вопроса отвечает эта команда. «Неверно» — минус стоимость, команда попадает в `triedTeamIds`, и вопрос можно перехватить любой другой (неверный перехват — тоже минус). «Верно» — плюс и закрыть.
- Таймер вопроса: длительность — `Question.timerSec`, ход таймера — `LiveState.timer` (момент окончания `endsAt` или остаток на паузе; функции в `live.ts`, тиканье — хук `src/useTimeLeft.ts`). Запускает ведущий (T), время можно выбрать на пульте у любого вопроса; зал только показывает. Заметка ведущему — `Question.hostNote`, в зале её нет.
- Пульт (`screens/HostApp.tsx`) — единственный источник состояния партии; экран зала (`screens/ScreenApp.tsx`) только показывает то, что прислал пульт.
- **Предпросмотр вопроса и история отмен существуют только на пульте и никогда не попадают в зал.** Не добавляй их в `LiveState`.

## Дизайн

- Тёмная графитовая тема; акцент — инверсия (белое с чёрным текстом) или фирменный цвет клиента.
- Токены Tailwind в `src/index.css` (`@theme`): `bg-bg` #26272B, `bg-cell` #34363C, `border-line` #55585F, `text-muted` #C4C6CC.
- Шрифты: `font-display` (Rubik Mono One) — заголовки, категории, номиналы; Inter — весь остальной текст, включая вопросы.
- Табло: категории строками, номиналы справа; сыгранная ячейка — пунктирная рамка. Ячейки стоят по порядку (`sortByValue`, при равной цене — как в игре), а не по цене: в строке может быть восемь «400». В категории до 10 вопросов (`MAX_QUESTIONS`), готовые сетки 5 / 8 / 10, новая игра — 10. Номинал в ячейке масштабируется под её ширину (`@container` + `cqw`), чтобы «1000» помещался.
- Кнопки и цели касания не меньше 44 px; настоящие `<button>` и `<a>`.
